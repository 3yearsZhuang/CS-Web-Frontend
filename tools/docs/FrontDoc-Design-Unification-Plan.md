## 1. 背景与动机：为什么需要设计统一

### 1.1 现状评估

项目已有成熟的"编辑式技术极简"视觉语言：

| 已有优势 | 说明 |
|---|---|
| 颜色/字体/圆角/阴影/层级/动效 | 已有集中 token |
| 基础组件体系 | Button / Badge / Title / DnaCard / CollapsingHero 已形成复用体系 |
| 品牌辨识度 | 12 栏栅格、数字章节标记、衬线标题、等宽元数据、发丝线、深蓝/琥珀主题 |
| 工程基础 | 深浅主题、响应式、键盘可达性与反馈状态已有工程基础 |

### 1.2 当前问题

问题不在缺少风格，而在**页面装配层的密度、层级和交互节奏尚未完全统一**：

| # | 问题 | 影响 |
|---|---|---|
| 1 | **首屏模式偏重** | 多个业务页复用大型折叠 Hero，用户进入高频任务时需要先经过较强的视觉叙事 |
| 2 | **页面结构不同构** | 首页、社区、活动、工具、后台各自形成局部布局，导航到新页面时认知模型会变化 |
| 3 | **视觉语汇叠加较多** | 编辑式、工业终端、像素融合、粒子特效同时出现时，信息优先级容易被装饰稀释 |
| 4 | **卡片语义不足** | 强调卡、普通内容卡、数据卡和操作卡有时使用相近皮肤，用户不易从外形预判用途 |
| 5 | **操作层级不稳定** | 同一页面可能并列出现多个高强调按钮，主任务不够聚焦 |
| 6 | **内容宽度不稳定** | 桌面端内容很宽但缺少稳定阅读列宽；移动端容易堆成长页面 |

## 2. 统一目标

### 2.1 核心目标

| 目标 | 说明 |
|---|---|
| **保留品牌 DNA** | 衬线大标题、像素/等宽元数据、数字章节、发丝线、深蓝/琥珀主题 |
| **建立稳定应用壳** | 全站统一顶栏、页面上下文、主内容区和辅助信息区 |
| **首屏先回答"三个问题"** | 我在哪里、现在有什么、下一步做什么 |
| **差异化首屏策略** | 高频任务页减少全屏 Hero；品牌页保留沉浸式 Hero |
| **组件外形表达语义** | 组件外形表达语义，而不仅表达风格 |
| **跨端一致信息顺序** | 桌面、平板、移动端保持相同信息顺序，只改变布局方式 |

### 2.2 设计原则

1. **语义优先于风格**：组件的视觉外形首先传达语义（这是什么类型的内容），其次才是风格
2. **密度优先于装饰**：高频任务页优先保证信息密度和操作效率，装饰性元素让位
3. **一致性优先于多样性**：同类内容在不同页面使用相同组件语义，不追求每页独特
4. **渐进增强**：从全局壳开始，逐页迁移，不做全量重构

## 3. 建议设计系统

### 3.1 三种页面模板

| 模板 | 使用场景 | 结构 |
|---|---|---|
| **Brand** | 首页、关于、招新 | 沉浸 Hero + 品牌叙事 + 单一 CTA |
| **Hub** | 社区、活动、工具、个人中心 | 紧凑 Page Header + 状态概览 + 主内容/侧栏 |
| **Task** | 编辑、考试、资源提交、后台 | 面包屑/返回 + 任务标题 + 固定操作区 + 聚焦内容 |

### 3.2 页面骨架

```text
Global Navbar
└─ Page Context Bar：章节编号 / 页面名 / 状态 / 主操作
   └─ Content Grid
      ├─ Main（8–9 栏）
      └─ Aside（3–4 栏，可折叠）
```

移动端顺序固定为：上下文 → 主操作 → 状态摘要 → 主内容 → 辅助信息。

### 3.3 组件语义体系

| 组件类型 | 语义 | 使用规则 |
|---|---|---|
| **Metric Tile** | 只展示关键数字 | 无大面积装饰 |
| **Action Card** | 可点击入口 | 保留 DNA 角标与硬阴影 |
| **Content Row** | 高密度信息列表 | 使用发丝线列表，不全部卡片化 |
| **Focus Panel** | 当前任务/推荐内容 | 允许主色底/主色边框，但每屏最多一个 |
| **Status Badge** | 状态标识 | 状态色只表达状态，不用作普通分类标签 |

### 3.4 视觉配额（硬性约束）

| 配额 | 规则 |
|---|---|
| 衬线大标题 | 每个首屏最多一个 |
| 硬阴影重点卡 | 每屏最多一个 |
| 主按钮 | 每屏最多一个；其他操作降为 outline 或文字链接 |
| 像素字体 | 仅用于编号、状态、标签和短按钮，不用于正文段落 |
| 装饰效果 | 粒子、扫描线、标题虚影仅用于 Brand 模板或关键空状态 |

## 4. 实施路线

### Phase 0：Demo 与评审

- 完成 `/design-demo`（静态数据模拟登录后的协会门户）
- 对比现有 `/tools`、`/events`、`/community` 的首屏信息效率
- 确认页面模板、卡片语义、密度和移动端顺序

### Phase 1：全局壳与原语

- 抽取 `PageContextBar`、`MetricTile`、`ActionCard`、`ContentRow`
- 收敛页面最大宽度、区块间距、主/次操作规则
- 为三类页面模板补齐文档和示例

### Phase 2：高频入口迁移

- 优先改造 `/tools`、`/community`、`/events`
- 保留数据逻辑，仅替换装配层和展示组件
- 每迁移一页补移动端与键盘检查

### Phase 3：任务页与详情页

- 统一返回路径、页面标题、状态区、提交操作区
- 统一 loading / empty / error / success 四态

### Phase 4：后台与移动端同步

- 后台采用更高密度的 Task 模板，不套沉浸式视觉
- 将稳定后的颜色、间距、状态和导航规则同步到 `CS-Mobile`

## 5. 验收标准

| # | 验收项 | 标准 |
|---|---|---|
| 1 | **首屏识别时间** | 进入任一 Hub 页面后，3 秒内能识别页面名称、当前状态和主操作 |
| 2 | **组件语义一致** | 同类内容在不同页面使用相同组件语义 |
| 3 | **响应式合规** | 360px、768px、1280px 三档无横向滚动和信息顺序变化 |
| 4 | **可达性** | 键盘焦点可见，交互目标不小于 44px |
| 5 | **主题兼容** | 深浅主题均满足正文与状态可读性 |
| 6 | **无新增硬编码** | 不新增硬编码品牌色、不新增第三套字体、不绕开现有基础组件 |
| 7 | **业务逻辑不变** | 页面迁移不改变 BFF/API、权限和业务状态逻辑 |

## 7. 结论与展望

### 7.1 一句话结论

> **项目已有成熟的视觉语言和组件体系，问题不在缺少风格而在页面装配层。通过建立三种页面模板（Brand/Hub/Task）、统一组件语义（Metric Tile/Action Card/Content Row/Focus Panel/Status Badge）和视觉配额（每屏最多一个主按钮/硬阴影卡/衬线标题），可以在保留品牌 DNA 的前提下提升信息密度、操作效率和跨端一致性。**

### 7.2 下一步行动

1. 完成 `design-demo` 静态 Demo 验证
2. 确认 4 个待评审决策项
3. 启动 Phase 1（全局壳与原语抽取）
